# Local comparison acceptance walkthrough

This feature stacks on the integrity foundation and adds no new dilution convention. Use hypothetical anonymous inputs; no real saved account data needs changing.

1. Existing current draft becomes the first baseline. Create up to three alternatives with **Duplicate active case**. Each copy initially has zero differences and preserves holder/round identities. Editing an alternative never changes the baseline.
2. Rename cases distinctly (1–80 characters). Pin any valid active case as baseline. The reference is explicit in both the picker and outcome table; editing that case updates the baseline. The baseline cannot be removed until a different case is pinned.
3. Remove round 2 and set the reserve to zero. Use $8M pre-money / $2M cash in round 1. Duplicate, then change the alternative cash to $3M. Combined founder ownership is **80.000% vs 72.727%**, difference **−7.273 pp**; new cash differs by **+$1,000,000**. Changed assumptions shows exactly that investment change. Values come from the existing engine, including whole-share rounding.
4. Review each founder separately in the outcome table. Duplicate founder display names remain distinct by identity. Renaming does not create a new holder. A holder missing from another case is explicitly “Not in case”. Loading unrelated inputs does not match people merely because names are equal.
5. Rename/reorder rounds, add a SAFE, or change reserve/grant settings in a copy. Changed assumptions shows the affected fields, added/removed entities, and funding order. Final modeled stage is explicit; comparisons of different round horizons are not presented as equivalent stages.
6. **Reset to baseline** copies current baseline inputs into the active alternative while preserving its name. Undo reset restores previous inputs. Remove a case and undo removal. Pin a new baseline and undo the baseline change. Later edits clear the undo checkpoint; reload does not retain undo history.
7. Enter an invalid pre-money or founder percentage. Normal results/export/autosave and case switching are blocked. No plausible delta is shown for that case. **Discard invalid edits** restores its last valid inputs. Reset/remove then undo a case with founder percentage 101: the display must return to 101 with its error, including when focused, until corrected or discarded.
8. Reload after a valid change. Case names, identities, inputs, active case, baseline, scenario schema, and calculation version survive. Reload after invalid edits restores the last valid workspace. A malformed/future workspace or model migration preserves exact original JSON before saving; storage/recovery failure cannot overwrite the previous workspace.
9. At 320, 390, 768, and 1440px, create four cases with a long name. All controls remain reachable without page overflow. Tables scroll inside named focusable regions. Use Tab/Enter to switch; focus follows the selected case after duplication/removal/pinning. Existing edit/results navigation remains available.
10. Export uses only the active case and includes its name in the filename. The workbook still uses the same validated financial export. Cloud Save is also active-case-only; the comparison workspace remains in this browser. Switching local cases clears the cloud-record association. Verify real cloud save/load separately with an allowed hypothetical test account; mocked lifecycle tests are not proof of authenticated backend behavior.

Required validation: the complete unit/React suite, production build, production dependency audit, foundation and comparison Chromium regressions. The financial engine fixtures remain unchanged. Preview verification must use the exact branch commit, keep Vercel protection enabled, and distinguish authenticated HTTP fetch from actual browser interaction.
